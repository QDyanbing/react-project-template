# 版本发布规范

## 目标与边界

本规范统一版本号、Git Tag、发布门禁、发布说明和不可变要求，确保版本可识别、变更可追溯、升级影响可判断。

发布平台、产物形式和部署流程由项目根据交付目标确定，所有发布方式均须遵守本规范。

## 版本号

版本号遵循 [Semantic Versioning 2.0.0](https://semver.org/)：

- `MAJOR`：存在不兼容的目录、配置、接口或使用方式调整，升级时需要迁移。
- `MINOR`：向后兼容地增加模板能力、内置模块或公共扩展点。
- `PATCH`：向后兼容地修复缺陷、完善已有能力或修正文档。
- 预发布版本只使用 `-rc.N`，例如 `1.2.0-rc.1`。
- 不使用 `+build` 元数据，源码定位由 Git Commit SHA 承担。

尚未正式发布时可以使用 `0.0.0` 作为占位版本。已经承诺稳定升级边界时从 `1.0.0` 开始，仍处于快速迭代阶段时可以使用 `0.x`。

版本号由维护者根据变更影响确定。

## 版本来源与 Tag

发布版本同时写入以下位置：

| 位置           | 格式                  | 示例     |
| -------------- | --------------------- | -------- |
| `package.json` | 不带前缀的 SemVer     | `1.2.0`  |
| Git Tag        | 带 `v` 前缀的相同版本 | `v1.2.0` |

必须遵守以下规则：

- `package.json` 与 Git Tag 的版本必须一致。
- Tag 必须指向已经合入默认分支的提交。
- Tag 使用 Annotated Tag，记录对应版本。
- 已推送的版本 Tag 不得删除后重建或强制移动。
- 版本修改必须通过 PR 接受检查和评审。

## 发布前置条件

创建版本 Tag 前必须确认：

- 本次版本包含的改动已经合入默认分支。
- Tag 目标提交的默认分支 CI 已全部通过。
- `package.json` 已更新为目标版本。
- 用户可见变更已经写入 PR 的 Changelog。
- 破坏性变更已经提供迁移说明。
- 文档与当前实现保持一致。

## 发布说明

每次发布都应提供面向使用者的发布说明，至少包含：

- 版本号和发布日期。
- 本次版本的变更摘要。
- 用户可感知的新增能力和重要修复。
- 配置、依赖或使用方式变化（如有）。
- 破坏性变更及迁移方式（如有）。
- 已知限制（如有）。

PR 中的 Changelog 是版本说明的原始输入。发布说明的载体不作限制，内容必须与目标版本一致。

## 发布流程

以发布 `v1.2.0` 为例：

1. 在 PR 中将 `package.json` 的 `version` 修改为 `1.2.0`，同步相关文档和迁移说明。
2. 合并 PR，并等待对应默认分支提交的 CI 全部通过。
3. 在对应的默认分支提交上创建并推送 `v1.2.0` Annotated Tag。
4. 编写发布说明并生成项目需要的交付物。
5. 验证交付物能够定位到同一个 Tag 和 Commit SHA。

Tag 推送后发现问题时不得移动原 Tag。完成修复后生成新版本：预发布阶段递增 `rc.N`，稳定版本根据变更影响递增 PATCH、MINOR 或 MAJOR。

## 发布产物

发布产物的类型和存储位置不作统一限制。任何交付物必须满足：

- 标明对应版本、Git Tag 和 Commit SHA。
- 稳定版本与预发布版本能够明确区分。
- 已发布的版本产物不得被同名覆盖。
- 保留历史版本或等效回滚依据。
- 回滚不依赖移动或重建已有版本 Tag。

## 验收标准

- 版本号能够表达升级影响。
- `package.json`、Git Tag 和发布说明使用同一个版本。
- 发布 Tag 只指向默认分支中已通过 CI 的提交。
- 用户可见变更能够从发布说明追溯到 PR 和 Commit。
- 破坏性变更包含迁移说明。
- 已推送的版本 Tag 不被覆盖。
- 发布产物能够追溯到对应版本、Tag 和 Commit SHA。

## 规范摘要

| 项目       | 规范                                              |
| ---------- | ------------------------------------------------- |
| 版本规则   | Semantic Versioning 2.0.0                         |
| 稳定版本   | `MAJOR.MINOR.PATCH`                               |
| 预发布版本 | 只使用 `MAJOR.MINOR.PATCH-rc.N`                   |
| 版本来源   | `package.json` 与 `v` 前缀 Annotated Tag 保持一致 |
| 版本决策   | 维护者根据变更影响人工判断                        |
| 发布门禁   | 默认分支已合并、CI 通过、Changelog 和迁移说明完整 |
| 发布实现   | 按项目交付目标配置                                |
| 发布产物   | 类型和存储位置不限，必须可追溯且不可覆盖          |
| 不可变边界 | 已推送的版本 Tag 不删除、不重建、不移动           |
